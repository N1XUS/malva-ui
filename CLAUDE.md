# Malva UI Library — Monorepo Index

This is the solution-level CLAUDE.md. It indexes all projects in the workspace and links to their individual documentation.

Coding standards and conventions are defined in best-practices.md (always loaded below) and the granular rule files in `.claude/rules/`:

@.claude/projects/best-practices.md

During development, refer to the individual project CLAUDE.md files for specific implementation guidelines, architectural decisions, and API documentation. Each project should have its own CLAUDE.md located at `apps/<app-name>/CLAUDE.md` or `libs/<lib-name>/CLAUDE.md`.
Analyze code only if context from the relevant project CLAUDE.md is not sufficient to answer the question. Always prefer the project-specific CLAUDE.md for implementation details and conventions related to that project.

## Migrations

Breaking API renames are logged under `docs/migrations/`. Most recent:

- [docs/migrations/2026-09-popup-fullscreen-per-open.md](docs/migrations/2026-09-popup-fullscreen-per-open.md) — **breaking, behaviour only** (nothing renamed, removed or retyped): `MlvPopup.isFullscreen()` is now **resolved once per open** instead of tracking `MlvBreakpointService` and the `mobileMode` / `mobileBreakpoint` inputs continuously. It stays public and still a `Signal<boolean>`; while an overlay is attached it reports the mode that overlay was built with, and it tracks the viewport again once the overlay is disposed. The overlay half of full-screen mode (global vs connected position strategy, `mlv-popup-fullscreen-pane`, the forced solid scrim, the block scroll strategy) is chosen at `Overlay.create()` time, and while CDK can restrategise, reclass and re-scroll-lock an attached overlay it cannot **add** a scrim to one, so the panel chrome holds still with it rather than half-converting — fixes #126 / #144, where a viewport crossing `md` mid-open left an anchored-looking panel inside a viewport-filling pane behind a modal scrim with its close button removed (and the reverse). Both `MlvPopupContainer` and standalone `MlvPopupTrigger` now pass `fullscreen: popup.lockFullscreenForOpen()`, so the flag the overlay is created with and the value `isFullscreen()` reports are the same read. Affects every `mobileMode="auto"` consumer — `mlv-select`, `mlv-combobox`, `mlv-day-picker`, `mlv-date-range-picker`, `mlv-time-picker` — all of which gain consistency rather than losing behaviour. Only code that deliberately converted a popup mid-open (e.g. a demo toggling `[mobileMode]`) needs a change: close and reopen.
- [docs/migrations/2026-09-core-date.md](docs/migrations/2026-09-core-date.md) — **breaking:** the date adapter (`MlvDateAdapter`, `MlvNativeDateAdapter`, `MLV_DATE_ADAPTER`, `MLV_DATE_LOCALE`, `provideMlvDateAdapter`, `MlvDateFormatOptions`) moved from `@malva-ui/core/calendar` to the new component-less entry point **`@malva-ui/core/date`**; no alias, only the import specifier changes (the `@malva-ui/core` root barrel still re-exports everything). Also **breaking for custom adapters:** `MlvDateAdapter<D>` gains six abstract time-of-day members (`getHours`, `getMinutes`, `createDateTime`, `addMinutes`, `differenceInMinutes`, `now`) plus inherited helpers (`withTime`, `startOfDay`, `minutesOfDay`, `shiftDays`, `compareDateTime`, `sameDateTime`) for `@malva-ui/scheduler`; `MlvNativeDateAdapter` implements them.
- [docs/migrations/2026-09-scrubber-extraction.md](docs/migrations/2026-09-scrubber-extraction.md) — the time picker's private drum-roll column became its own component, **`@malva-ui/core/scrubber`** (`mlv-scrubber`), generalised to either axis (an `orientation` input), to a generic item type `T` with a `displayWith` format hook (the zero-padded two-digit numeral is now the time picker's own formatter), and to RTL — the horizontal variant is on the inline axis, so it mirrors: logical snap port / list padding / centre stripe, a physical→logical conversion of `scrollLeft`, and a scope-aware `Directionality` provided on the component so `@angular/aria`'s arrow keys follow a `[dir]` subtree and not only the document. **No TypeScript API change** — `MlvTimePickerColumn` was `@internal` and never exported — and **no custom property disappears, no consumer override breaks**: `mlv-time-picker` declares the whole `--mlv-tp-*` → `--mlv-scrubber-*` alias layer on the `<mlv-scrubber>` element itself (all nine published names, `--mlv-tp-side-rows` included). A custom property's `var()`s are substituted on the element that _declares_ it, so aliasing on the leaf — and nowhere above it — is what keeps an override written on the panel, on `.mlv-time-picker__columns` or on the strip itself inherited into the alias and reaching the drum. **Breaking only for CSS written against the drum's BEM classes:** `.mlv-time-picker-column`, `__track`, `__list`, `__item`, `__item--selected` → `.mlv-scrubber…`.
- [docs/migrations/2026-09-drawer-header.md](docs/migrations/2026-09-drawer-header.md) — no API removals; `MlvDrawerHeader` is now a **component** (`mlv-drawer-header, [mlvDrawerHeader]`) that renders title → projected content → a trailing `mlv-button-close` (omit with `closable="false"`), pins **compact** density on its content so `mlv-drawer-sections` and projected `mlvButton`s share the close button's 36px row, and registers its `title` (or a direct-child heading / `[mlvDrawerTitle]`) as the drawer's `aria-labelledby` — service-opened drawers included, via `MlvDrawerRef`. The resizable bottom sheet's drag handle merges into the header band (69px instead of 48 + 69). `MLV_DRAWER_I18N` gains `closeDrawer`. Consumers that hand-rolled a close button now render two — delete theirs or pass `closable="false"`; drawers whose body holds `[mlvDrawerSection]`s (`<h5>`) pass `level="4"` on the header. Adjacent: `minSize` is now bound (and viewport-clamped), the side-drawer resize handle sits in a 48px gutter instead of pushing the header off the panel, and the handle's `aria-valuenow` is a signal that follows the clamped box.
- [docs/migrations/2026-09-data-source-sort-semantics.md](docs/migrations/2026-09-data-source-sort-semantics.md) — **breaking, behaviour only** (no API change, nothing to edit at a call site): `MlvArrayDataSource`'s sort order changes for two inputs. `mlv-data-table` is the only component that sorts on its own, so it is the only one affected without touching its own code; `mlv-select` / `mlv-combobox` / `[mlvAutocomplete]` inherit sorting through `MlvSelectDataSource` but never set a sort themselves, so they change only when a consumer sorts the source it was given. A nullish **row** — an array element that is literally `null`/`undefined`, not a row whose cell is nullish — is now an absent record and sinks to the end in **both** directions, `null` and `undefined` indistinguishable and the trailing run in input order; previously a `null` row led under `asc` (it collated as `''`) while an `undefined` row trailed because `Array.prototype.sort` hoists `undefined` elements itself. Nullish **cell values** are unchanged and still collate as `''`. The numeric branch is now a total order `-Infinity < finite < Infinity < NaN` instead of `av - bv`, which returned `NaN` for non-finite pairs and left the permutation implementation-defined — reachable with no `NaN` in the data at all, since `Infinity - Infinity` is `NaN`. `NaN` is a rank, not a pinned end: it trails under `asc` and leads under `desc`, matching PostgreSQL. `-0`/`0` still tie. Both were deferred deliberately by #10 and are resolved as #83 and #81; the mixed number/string branch remains non-transitive and is explicitly out of scope.
- [docs/migrations/2026-08-scrollbar-viewport-tabindex.md](docs/migrations/2026-08-scrollbar-viewport-tabindex.md) — **breaking:** `mlv-scrollbar`'s `viewportTabIndex` is now a pure passthrough. Type narrows `number` → `-1 | 0 | null` and the default changes `0` → `null`, which emits **no `tabindex` attribute at all**; `0` no longer means "auto" but a literal, unconditional tab stop (plus `role="group"` + the resolved `aria-label`). The content-tabbability mechanism behind the old auto mode is deleted — the `MutationObserver` over projected content, its `FOCUSABLE_CANDIDATE_SELECTOR` scan and the `InteractivityChecker` (so `@angular/cdk/a11y` is no longer a scrollbar dependency). Consumers relying on the old default must pass `[viewportTabIndex]="0"`; with no attribute, focusability of a non-focusable overflowing scroller falls to native browser scroller focusability (Chrome 127+, Firefox). Existing `-1` call sites are unaffected.
- [docs/migrations/2026-08-visual-harmonization.md](docs/migrations/2026-08-visual-harmonization.md) — no API removals; a token + component visual restyle across `@malva-ui/styles` and most of `@malva-ui/core`. Radius roles fixed per-role instead of scaling per density/size (button/input → `l`/8px at every density, was `s`→`2xl` across the ramp; card → fixed `xl`/12px at every size; tag → full pill, was `s`/4px; panel → `l`/8px, was `xl`/12px; dialog surface → `2xl`/16px, was a hardcoded `l`/8px). New selected-state tokens (`--mlv-background-selected`/`-hover`, `--mlv-text-on-selected`) so persistent selection never borrows the pressed `-active` fill; disabled is now a declared `--mlv-background-disabled` surface, not an opacity multiply, with a fixed disabled-beats-pressed cascade order on button/button-toggle. `mlv-button[variant="transparent"]` glyphs are neutral chrome, not accent-colored (`outlined` unaffected). `mlv-list`'s default variant is now hairline-separated with zero per-row radius/background instead of spaced per-row cards. `mlv-segmented`/boxed `mlv-tabs` keep their raised-pill look and gained a dark-mode lift fix. New component `mlv-icon-toggle` (`@malva-ui/core/icon-toggle`, chromeless glyph-only toggle). Motion literals were swept onto the shared duration/easing tokens with reduced-motion coverage now at 100%.
- [docs/migrations/2026-08-options-data-source.md](docs/migrations/2026-08-options-data-source.md) — the data-source primitives moved from `@malva-ui/core/data-table` to the new **`@malva-ui/cdk/data-source`** (still re-exported by the table; the operator union is now `MlvDataSourceFilterOperator`, with `MlvDataTableFilterOperator` as a deprecated alias), `MlvDataSource.loading` and natural-field search (`keys: []`) are new, and `normalizeForMatch` moved to `@malva-ui/cdk/utils`. `mlv-select` / `mlv-combobox` / `[mlvAutocomplete]` `options` now accept `T[] | Observable<T[]> | MlvDataSource<T>` with lazy paging, plus `searchFn` + `searchDebounce`; `mlv-select` gains `compareWith`, a loading variant for an unresolved value, and `searchable` (in-dropdown search field that takes over `role="combobox"` while open, the trigger stepping down to `role="button"`). New select/combobox i18n keys in every locale, and `mlv-dropdown-panel` gains `loadingMore` / `hasMore` / `infiniteScrollThreshold` / `loadMore`.
- [docs/migrations/2026-08-dialog-composition.md](docs/migrations/2026-08-dialog-composition.md) — `@malva-ui/core/dialog` rebuilt on `@angular/cdk/dialog`: every dialog is a `<mlv-dialog>` surface with `mlv-dialog-header` / `mlv-dialog-body` / `mlv-dialog-footer` parts and `[mlvDialogClose]`; the `<mlv-dialog [(opened)]>` host, `*mlvDialogHeaderDef`, `mlvDialogContent`, `DialogBodyDirective`, `showCloseButton` and the service header row are gone; new `ng-template[mlvDialog]` sugar, `closable`, `appearance`/`panelClass`/`backdropClass`/`role` config, `MlvDialogService.closeAll()`, `MlvDialogRef` wraps the CDK ref.
- [docs/migrations/2026-08-sidebar-state-tokens.md](docs/migrations/2026-08-sidebar-state-tokens.md) — sidebar row states moved onto three component-scoped variables on `.mlv-sidebar` (`--mlv-sidebar-hover-bg`, `--mlv-sidebar-active-bg`, `--mlv-sidebar-rail-color`, each read with the old global as the `var()` fallback) and `mlv-page-shell` remaps them (plus the `--mlv-background-neutral-1` hover/active ramp) from its chrome foreground. Visual defaults: active plain items now get the accent-pale pill, collapsed group icon hover matches item hover, and an active row keeps its pill through hover. Behaviour: the group flyout closes on child activation, and the accordion never opens while the sidebar is collapsed.
- [docs/migrations/2026-08-form-field-surface.md](docs/migrations/2026-08-form-field-surface.md) — `required`, `description` and `ariaLabel` moved onto `MlvSignalFormUiControlBase` (every form control inherits them; `<mlv-description>` slot; `MlvLabel.required` marker; per-control `messageId` helpers removed, `MlvTextarea.countId` is now a signal); textarea counter finally renders; checkbox/switch `label` renders visible text; `autoErrorMessage` falls back to a translated generic message.
- [docs/migrations/2026-08-overlay-chrome-and-focus.md](docs/migrations/2026-08-overlay-chrome-and-focus.md) — service-opened dialogs render Malva's header row (`MlvDialogConfig.title`, `showCloseButton` default `true`) and get an accessible name; new `initialFocus` on `MlvOverlayHostBase`/`MlvBaseOverlayConfig` (`'auto'` skips close button + scroll viewport); `MlvDialogService.confirm()`; drawers clamp `size` to the viewport and honour `maxSize`; `mlv-scrollbar` viewport is a tab stop only when its content is not. **Its dialog half is superseded by the composition rebuild above** — the service draws no header row and `showCloseButton` is now `closable` — and **its `mlv-scrollbar` half is superseded by the viewport-tabindex entry above**: the auto mode is gone, `viewportTabIndex` defaults to `null` and emits no attribute. The drawer and `initialFocus` parts still stand.
- [docs/migrations/2026-08-button-icon-only-default-variant.md](docs/migrations/2026-08-button-icon-only-default-variant.md) — icon-only buttons (`shape="square|circle"` with no projected text) are inferred without `mlvButtonIcon` and default to `variant="secondary"` instead of `primary`.
- [docs/migrations/2026-08-page-dock-floating-and-toast-inset.md](docs/migrations/2026-08-page-dock-floating-and-toast-inset.md) — `mlv-page-dock[appearance="floating"]` paints the gradient-masked backdrop; dock geometry survives wrappers; sticky dock publishes `--mlv-page-dock-height` and bottom toasts respect `--mlv-toast-inset-block-end`; `MlvActionBar.wrap`.
- [docs/migrations/2026-08-sidebar-responsive-and-row-rhythm.md](docs/migrations/2026-08-sidebar-responsive-and-row-rhythm.md) — `MlvSidebar.ariaLabel`, `collapseBelow` (auto-offcanvas below a breakpoint, `mlv-sidebar-trigger` becomes a menu button, `[sidebar]` input for triggers outside the sidebar), shared `--mlv-sidebar-row-height`; offcanvas host no longer reserves inline width.
- [docs/migrations/2026-08-editor-package.md](docs/migrations/2026-08-editor-package.md) — the editor left `@malva-ui/core` and is now its own published package, **`@malva-ui/editor`**. `@malva-ui/core/editor` no longer resolves and the core root barrel no longer re-exports it; no deprecated alias. Every exported symbol keeps its name — only the import specifier changes. All twelve `@tiptap/*` peers moved with it, so core now declares no Tiptap peers and no `peerDependenciesMeta` at all.
- [docs/migrations/2026-07-toast-shape-icon-announcement.md](docs/migrations/2026-07-toast-shape-icon-announcement.md) — toast gained `shape` (`'default'`/`'pill'`) and a working tone-derived `icon`; `mlv-toast-item` now hugs its content; **`resolveToastRole()` → `resolveToastPoliteness()`** and both toast and notification items dropped their `role`, announcing through the CDK `LiveAnnouncer` instead (requires the `.cdk-visually-hidden` rules now shipped in `styles/malva-ui.css`).
- [docs/migrations/2026-07-mlv-prefix.md](docs/migrations/2026-07-mlv-prefix.md) — prefixed every publicly exported class/type/interface with **`Mlv`** and dropped the `Component`/`Directive` suffix from `@Component`/`@Directive` classes (`ButtonComponent` → `MlvButton`, `ButtonIconDirective` → `MlvButtonIcon`, `MlvButtonShape` → `MlvButtonShape`). Also dropped the `.component`/`.directive` segment from filenames under `libs/`. No deprecated aliases.
- [docs/migrations/2026-07-api-unification-tone-size.md](docs/migrations/2026-07-api-unification-tone-size.md) — unified the semantic-colour input to **`tone`** (`MlvTone` in `@malva-ui/cdk/utils`) across display surfaces (`alert`, `toast`, `notification`, `timeline`, `tile`, `loader`, `progress`, `badge`, `chip`, `tooltip`); standardised values on `'danger'`/`'info'`; and moved `ButtonSize`/`ProgressSize`/`DialogSizePreset` to the letter scale `xs|s|m|l|xl` (default `'m'`). Those type names later gained the `Mlv` prefix — see above.

# General Guidelines for working with Nx

- For navigating/exploring the workspace, invoke the `nx-workspace` skill first - it has patterns for querying projects, targets, and dependencies
- When running tasks (for example build, lint, test, e2e, etc.), always prefer running the task through `nx` (i.e. `nx run`, `nx run-many`, `nx affected`) instead of using the underlying tooling directly
- Prefix nx commands with the workspace's package manager (e.g., `pnpm nx build`, `npm exec nx test`) - avoids using globally installed CLI
- You have access to the Nx MCP server and its tools, use them to help the user
- For Nx plugin best practices, check `node_modules/@nx/<plugin>/PLUGIN.md`. Not all plugins have this file - proceed without it if unavailable.
- NEVER guess CLI flags - always check nx_docs or `--help` first when unsure

## Scaffolding & Generators

- For scaffolding tasks (creating apps, libs, project structure, setup), ALWAYS invoke the `nx-generate` skill FIRST before exploring or calling MCP tools

## When to use nx_docs

- USE for: advanced config options, unfamiliar flags, migration guides, plugin configuration, edge cases
- DON'T USE for: basic generator syntax (`nx g @nx/react:app`), standard commands, things you already know
- The `nx-generate` skill handles generator discovery internally - don't call nx_docs just to look up generator syntax
