---
title: Layout — height and toolbar placement
---

By default the editor **grows with its content**. It never shows a scrollbar
of its own, and a wheel, touch or keyboard scroll over it always reaches the
page. Wide tables and code blocks keep their own horizontal scroll, which
never captures a vertical wheel.

`height` fixes the surface (toolbar plus content), and `maxHeight` lets it
grow up to a cap. Either one turns the content viewport into a scroll
container. A number is px, and a string is any CSS length. `minHeight`
replaces the `8rem` floor without capping. Under a cap the cap wins, and the
floor then applies to the content inside the scroller, so a compact capped
editor also sets a smaller `minHeight`. Only these inputs cap:
`--mlv-editor-height` / `--mlv-editor-max-height` written in CSS alone have no
effect.

`toolbarPosition` puts the docked toolbar above or below the content, and the
Tab order follows. `toolbarSticky` pins that bar while the editor is on
screen, and `--mlv-editor-toolbar-sticky-offset` clears a fixed app header
(this page sets it to the docs' `5.5rem`). When the caret moves toward a
sticky bar, the editor scrolls it clear. Sticky applies to an **uncapped bar**
only: a capped editor scrolls inside its own viewport, which the bar sits
outside, so the switch is disabled while a height cap is selected.

`toolbarAppearance="floating"` turns the toolbar into a **selection bubble**.
It appears above a non-empty selection (below, when the window's or a capped
scroller's edge leaves no room), follows it while the content scrolls, and
hides on a bare caret, on blur, while dragging a block and during IME
composition. Press **Alt+F10** in the content to summon it at the caret and
move focus into it, and **Escape** to dismiss it with the selection intact.
`toolbarPosition` and `toolbarSticky` do not apply to it.

`toolbarAppearance="clean"` keeps that bubble and adds a gutter **"+"**
beside the block under the pointer or caret, which opens an insert menu —
example 14 walks through it. It has no bar either, so the Sticky switch stays
disabled.

A `readonly` editor renders no toolbar in any appearance: no bar, no bubble,
no "+", and no space kept for any of them.

Zoom reflows an uncapped editor, like browser zoom, and magnifies a capped one
inside its own scroller.
