## Virtual columns

Set `virtualItemSize` to the fixed card height in **pixels** and every cell renders through a `cdk-virtual-scroll-viewport` instead of a plain container — 500 cards here, of which only a window is ever in the DOM. A value that is not a finite number greater than zero is ignored and the board renders normally.

The size is a contract, not a hint: CDK's fixed-size strategy computes scroll offsets from it, so cards must actually be that tall. The board publishes it back as `--mlv-taskboard-virtual-item-size` and applies it as a `min-block-size` on each card, so a card that overflows grows the row and drifts out of sync. The scrolling cell itself takes its height from `--mlv-taskboard-cell-block-size` (default `20rem`); override that custom property rather than styling the viewport.

Three consequences worth knowing:

- **A DOM index is not a bucket index.** Every index the board reads back from a drop is translated through the cell's rendered window before it becomes a position in the column, so a card dropped at the top of a scrolled cell lands where it looks like it landed.
- **Keyboard focus scrolls first.** Moving to a card outside the window scrolls it in and focuses it after that render, so the roving tab stop never lands on an element that does not exist.
- **Printing renders everything.** `print()` drops virtualization for one render so a printed board holds every card; a print the reader starts themselves (<kbd>Ctrl</kbd>+<kbd>P</kbd>) still only holds the rendered windows.

`mlvTaskboardColumnContentDef` replaces the whole cell, viewport included, so a board that projects that slot is not virtualized — the projected template owns its own scrolling.

### Filtering without lying about capacity

`visibleItems` is a **view**, not a replacement: bind the filtered array to it and leave `items` canonical. WIP counts, transition checks and `canDropFn` keep reading `items`, so filtering the board never makes a full column look like it has room. Passing `undefined` (this example's empty query) means "no filter". Selection keys for filtered-out cards survive too — they are never pruned.

Inputs used: `virtualItemSize`, `visibleItems`.
