---
title: Virtual Scroll
---

Set `[virtualScroll]="true"` to render large datasets efficiently via Angular CDK's `cdk-virtual-scroll-viewport`. Only the rows currently in view are kept in the DOM; as the user scrolls, rows are recycled. This example renders **10,000 transactions** without any noticeable lag.

To support sticky headers and pinned columns, the component splits the table into three separate `<table>` elements in virtual mode:

- a header table outside the viewport,
- a body table inside the `cdk-virtual-scroll-viewport` using `*cdkVirtualFor`,
- an optional footer table below the viewport.

A shared `<colgroup>` and `table-layout: fixed` keep column widths aligned across the split tables. The outer table wrapper remains the only user-facing horizontal scroller; its position and programmatic viewport movement are synchronized so recycled body rows, focus changes, and pinned columns stay aligned with the header. Native scrollbar-gutter measurement keeps right-pinned cells aligned and extends the horizontal range far enough to reveal the complete last column on platforms with non-overlay scrollbars.

**No row height to pass.** The viewport positions off-screen rows by the row height the table actually renders, which it measures — so switching this example's density, zooming the browser's font size, or overriding `--mlv-dt-row-height` on the table keeps scrolling smooth. The measurement is the row token, not the cell content: a cell template taller than `--mlv-dt-row-height` needs the property raised on the table (to the content height + 1px for the row separator). `[rowHeight]` remains for forcing a fixed pixel pitch, and then does not follow density or font size.

Virtual scroll is mutually exclusive with `paginationMode="infinite"` — the infinite-scroll directive is automatically disabled while `virtualScroll` is on. Use the classic paginator or no pagination at all with this mode.
