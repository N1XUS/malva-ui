Before you start

You need an existing Angular application and permission to update its dependencies and workspace configuration. Commit or stash local changes first so the generated setup is easy to review.

Install with the guided setup

The Angular CLI runs the Malva UI installation schematic and uses your workspace package manager. The command is safe to run again: existing dependencies, styles, and providers are not duplicated.

  1. 1

    Choose the application

    A workspace with one Angular application is selected automatically. In a multi-application workspace, identify the target explicitly:

    ng add @malva-ui/core --project my-app
  2. 2

    Answer the setup questions

    Press Enter to accept the recommended defaults, or choose values that match your product.

    Initial theme
    light or dark. The default is light.
    Component density
    tight, compact, comfortable, spacious, or airy. The recommended default is comfortable.
    Global styles
    Adds Malva UI tokens, reset styles, and animations to the build. Keep this enabled unless your workspace manages them centrally.
    Application providers
    Bootstraps the selected theme and density. Keep this enabled for the standard setup.
  3. 3

    Review the generated changes

    The installer makes three focused updates:

    • Adds matching @malva-ui/core, @malva-ui/cdk, and @malva-ui/i18n dependencies.
    • Adds node_modules/@malva-ui/core/styles/malva-ui.css to the application's build styles.
    • Adds provideDefaultTheme() and provideMlvDensity() to the root providers of a standalone or NgModule application.

Supply every choice on the command line for CI, reproducible project templates, or other non-interactive environments.

Installer options and defaults
Option Purpose Default
--project Target Angular application name. The sole application
--theme light or dark. light
--density One of the five global density levels. comfortable
--include-styles Add the packaged global stylesheet. true
--configure-providers Add the theme and density providers. true
--theme-storage-key Browser storage key used to persist the theme. mlv-theme
--skip-install Update dependencies without running the package manager. false

To manage styles or providers yourself, pass --no-include-styles or --no-configure-providers.

Troubleshooting

Run the installer again with --project <application-name>. The installer does not guess when more than one application is available.

Confirm that node_modules/@malva-ui/core/styles/malva-ui.css appears in the target application's build styles, then restart the development server.

Check the root provider list for provideDefaultTheme() and provideMlvDensity(). A saved theme under the configured storage key can override the initial theme on later visits.

Resolve the package-manager error and run the same command again. The schematic skips configuration that is already present.

Versioning and support

All six packages share one version and are released together. The versioning policy states which surfaces are public API — TypeScript exports, component selectors, inputs, injection tokens, --mlv-* custom properties, BEM class names and i18n keys — what a major, minor and patch may each change, how long a deprecated symbol keeps working, and how long a superseded major is supported.
